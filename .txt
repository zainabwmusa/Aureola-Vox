# 10. How You Should Build It

Since you're learning full-stack development, I'd approach this in stages rather than building every page simultaneously.

### Phase 1 — Planning

* Confirm Aureola Vox's mission, vision, programs, and audience.
* Collect its logo, photographs, and official contact information.
* Decide the brand colors and typography.
* Sketch the homepage layout.

### Phase 2 — HTML Structure

Build the homepage first.

Organize the page using semantic HTML elements:

```html
<body>
    <header>
        <!-- Navigation -->
    </header>

    <main>
        <section id="home">
            <!-- Hero -->
        </section>

        <section id="about">
            <!-- Introduction -->
        </section>

        <section id="programs">
            <!-- Focus areas and programs -->
        </section>

        <section id="impact">
            <!-- Achievements and stories -->
        </section>

        <section id="events">
            <!-- Events -->
        </section>

        <section id="testimonials">
            <!-- Testimonials -->
        </section>

        <section id="join">
            <!-- Get involved -->
        </section>
    </main>

    <footer>
        <!-- Footer content -->
    </footer>
</body>
```

### Phase 3 — CSS Styling

Work on the following in order:

1. Global styles and typography.
2. Navbar.
3. Hero section.
4. Section spacing and backgrounds.
5. Cards and grids.
6. Buttons and hover effects.
7. Footer.
8. Responsive layouts.

Use **CSS Grid** for layouts involving rows and columns, **Flexbox** for one-dimensional alignment, and normal document flow where neither is necessary.

### Phase 4 — Responsive Design

Test the website on:

* Desktop.
* Tablet.
* Mobile.

Pay particular attention to navigation, heading sizes, image cropping, card layouts, and horizontal overflow.

### Phase 5 — JavaScript

Add functionality where necessary:

* Mobile navigation.
* FAQ accordions.
* Form validation.
* Interactive elements.
* Event filtering, if needed.

Avoid adding JavaScript to elements that can work with HTML and CSS alone.

### Phase 6 — Backend

Once the frontend is stable, determine whether the organization needs:

* Contact form processing.
* Volunteer or membership applications.
* An event registration system.
* An admin dashboard.
* A database.
* A content management system.

These are optional features based on the organization's actual requirements, not prerequisites for the initial website.

## My Recommendation

**Start with the homepage, but plan the entire website before coding.**

The homepage establishes your typography, spacing, color palette, buttons, cards, and overall layout. Once those design decisions are consistent, building the remaining pages becomes easier.

Before finalizing the skeleton, establish these three things:

1. **The organization's actual identity:** Its mission, vision, existing programs, and target audience.
2. **The website's primary objective:** Whether it mainly promotes the organization, recruits volunteers, registers participants, publicizes events, attracts partners, or combines these goals.
3. **The available assets:** Logo, brand colors, photographs, official copy, and contact details.

These decisions determine which sections belong on the website and which features you actually need to build.





























Then treat **Aureola Vox as a multi-page website project**, with separate HTML pages, shared design components, and a clear file structure.

Your project structure could look like this:

### How the pages connect

For example, when someone visits the homepage and clicks **About Us**, the browser opens `pages/about.html`. The same navigation system should appear across the pages so visitors can move between them easily.

### How I'd approach the project

Build it in stages:

1. **Project setup:** Create the folders and files.
2. **Design system:** Establish typography, colors, spacing, buttons, and reusable styles.
3. **Shared navigation and footer:** Build these once and maintain consistency across pages.
4. **Homepage:** Establish the website's overall visual identity.
5. **Remaining pages:** Build each page according to its specific purpose.
6. **Responsive design:** Ensure the entire website works on mobile, tablet, and desktop.
7. **JavaScript functionality:** Add navigation interactions and other required features.
8. **Backend integration:** Add form processing, event registration, or other dynamic features if needed.
9. **Testing and deployment:** Test links, forms, responsiveness, accessibility, and performance before publishing.

**One important distinction:** A multi-page website doesn't necessarily need a separate CSS file for every page. A shared `style.css` can handle the global design, while additional CSS files can be introduced for page-specific styles when necessary.

Since you're building this as a real organizational website, plan the architecture first, then develop each page systematically rather than writing everything in one HTML file.
